# Content Guidelines

All copy lives in `src/content/`. Components never hard-code portfolio claims.

## Rules

1. **Verified facts only.** If it is not confirmed by the owner, it does not ship. Unknowns stay out; they are not filled with plausible text.
2. **No invented metrics.** No percentages, user counts, uptime, or performance numbers unless the owner gives the number and confirms it can be shared.
3. **Exact titles.** Use the official job title. Describe scope honestly ("led the frontend team", not "built the platform").
4. **Confidentiality.** No client names unless approved. No internal system names, endpoints, schemas, screenshots, source code, or confidential workflows. Describe domains generically ("a general insurance provider").
5. **No fake links.** Only real, authorized URLs. Private projects show no repo or demo actions at all.
6. **No availability claims.** Never write "open to work" or "available for hire" unless the owner says so.
7. **Plain, specific language.** Avoid "passionate", "cutting-edge", "rockstar", "synergy", or "10x". Prefer verbs that describe what was actually done: led, designed, implemented, clarified, reviewed, mentored.
8. **Featured ≠ exhaustive.** Say the projects are selected examples.

## Role accuracy (must hold everywhere, including AI answers)

- **Ecoinsoft — Frontend Team Leader.** Led frontend engineers, guided backend developers on business workflows, clarified requirements, supported clients, and coordinated technical solutions. Do **not** claim ownership or implementation of the whole General Insurance backend.
- **Aibodia — Project Leader / Team Lead.** Hands-on backend and frontend work plus leadership. Do **not** mention formal Scrum ceremonies or scheduled sprint planning.

## Case study template

| Field         | Notes                                                                                                             |
| ------------- | ----------------------------------------------------------------------------------------------------------------- |
| Title         | Generic, descriptive ("Real-Time Auction Platform")                                                               |
| Overview      | 1–2 sentences                                                                                                     |
| Role          | Official title + what that meant on this project                                                                  |
| Context       | Domain and the kind of organization, anonymized                                                                   |
| Challenge     | Business or technical problem                                                                                     |
| Contributions | Personal work only, as bullets                                                                                    |
| Approach      | Techniques and decisions, at a sanitized level                                                                    |
| Outcome       | **Omit unless verified**                                                                                          |
| Technologies  | Real stack only                                                                                                   |
| Privacy note  | "Professional project. Code, data and client details are confidential; details are described at a general level." |

## Architecture diagrams

Only simplified boxes such as "Client → API → Cache → Database". No real service names, hosts, queue names or data fields.

## Voice

First person, calm and direct. Short paragraphs. Write the way the owner would explain their work to a peer.

## AI assistant answers

The assistant is bound by the same rules. If the content does not cover a question, it says so and points to Contact.
